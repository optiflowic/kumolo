# Cognito User Pools — Input Validation

URL: https://docs.aws.amazon.com/cognito-user-identity-pools/latest/APIReference/
Model: botocore `cognito-idp/2016-04-18/service-2.json` (upstream `develop`)
SDK: github.com/aws/aws-sdk-go-v2/service/cognitoidentityprovider
Last verified: 2026-10-12

Applies to every operation the router dispatches (all `case "<Operation>":` entries in
`internal/cognito/router.go`). Runs on the request as read by `input_deserialization.md`.

## Contract

- The router validates the request body against the model **before** it calls the handler.
  A violation is reported ahead of any pool, client, user or group lookup and ahead of
  access-token and session verification.
- A violation returns HTTP 400 `InvalidParameterException`. Nothing is read from or written
  to storage.
- Checked: top-level input members that are strings or integers.

| Constraint | Applies to | Constraint text in the message |
|---|---|---|
| required | any member type | `Member must not be null` |
| pattern (full match) | string | `Member must satisfy regular expression pattern: <pattern>` |
| enum | string | `Member must satisfy enum value set: [A, B]` |
| max length | string | `Member must have length less than or equal to <n>` |
| min length | string | `Member must have length greater than or equal to <n>` |
| max value | integer | `Member must have value less than or equal to <n>` |
| min value | integer | `Member must have value greater than or equal to <n>` |

- An omitted member and a JSON `null` are the same: a violation only if the member is required.
- Member names are matched exactly; the last of duplicate members is the one checked (see
  `input_deserialization.md`).
- An explicit empty string is a value. It fails `min >= 1`, any pattern that needs one
  character, and any enum.
- Every violation is reported, not only the first.

## Message format

```
<N> validation error(s) detected: Value '<value>' at '<memberName>' failed to satisfy constraint: <constraint>[; Value ...]
```

- `error` for one violation, `errors` for more.
- `<memberName>` is the member name with a lower-case first letter (`UserPoolId` → `userPoolId`).
- A missing required member is shown as `Value null at '<memberName>'`.
- Members whose shape is marked sensitive in the model (`AccessToken`, `Session`, `ClientId`,
  `Username`, passwords, `SecretHash`, `UserCode`, `Token`, `ClientSecret`) omit the value:
  `Value at '<memberName>'`.

## Verified against real AWS

Checked with live calls on 2026-10-11 (`cognito-idp.ap-northeast-1`), recorded in issue #609:

| Request | Response |
|---|---|
| `DescribeUserPool` `{"UserPoolId":"!!!"}` | 400 `InvalidParameterException`, `1 validation error detected: Value '!!!' at 'userPoolId' failed to satisfy constraint: Member must satisfy regular expression pattern: [\w-]+_[0-9a-zA-Z]+` |
| `GetUser` `{"AccessToken":"!!!"}` | 400 `InvalidParameterException`, `1 validation error detected: Value at 'accessToken' failed to satisfy constraint: Member must satisfy regular expression pattern: [A-Za-z0-9-_=.]+` |

Everything else in this memo follows the model and the same message convention, and has not
been confirmed with a live call: the text for the other constraint kinds, the wording for
several violations in one request, and the rejection of an empty-string enum member.

## Implementation

- `internal/cognito/validation.go`: `validateInput`, called from `Router.serveHTTP` after
  `decodeInput`.
- `internal/cognito/validation_gen.go`: the input shape graph, generated by
  `tools/genvalidation` (`make genvalidation`). Do not edit by hand.
- Regenerate when the model is updated or an operation is added to the router.
  `TestInputRules_CoverEveryDispatchedOperation` fails if an operation has no table entry.
- The table is generated from upstream botocore, not from the awscli2 pinned in the dev shell
  (2.35.11), whose model still has `SessionType` max 2048 instead of 4096. Pass
  `COGNITO_MODEL=<service-2.json>` to `make genvalidation` / `make gencases` until the pinned
  awscli2 catches up.
- Handlers keep only checks the model does not express (for example, `AccessToken` and
  `Session` being mutually exclusive, or attribute names kumolo supports).

## kumolo Deviations

- Members nested inside structures, lists and maps are not validated against the model
  (for example `UserAttributes[].Name`, `Tags` keys, `AuthParameters`). List and map sizes are
  not validated either. Handlers check some of these themselves; see the operation memos.
- Length is counted in Unicode code points.
- Violations are listed in alphabetical order of the member name. Within one member the
  order is pattern, enum, maximum, minimum. The order AWS uses, across members or within one,
  is not confirmed.
- `ClientId` on `DescribeUserPoolClient`, `UpdateUserPoolClient` and `DeleteUserPoolClient`
  must additionally be in the form kumolo issues (26 lower-case alphanumerics); see
  `user_pool_client.md`.
- The SRP `Session` kumolo issues is about 2,600 characters, longer than the sessions AWS
  issues but within the model limit of 4096.
